6. TECHNISCHE STOLPERSTEINE (WICHTIG FÜR NEUE AGENT-SITZUNG)
--------------------------------------------------------------------
a) Der verbundene lokale Ordner (gemountet über Cowork-Sandbox) lässt
   KEIN Löschen/Unlinken von Dateien zu (EPERM-Fehler bei rm/mv-
   Überschreiben). Workaround: Dateien innerhalb desselben
   Verzeichnisses UMBENENNEN (mv funktioniert), nicht löschen. Für
   echtes Löschen braucht es den Nutzer (Finder) oder ein Skript,
   das außerhalb dieses Mounts läuft.

b) Git-Befehle (add/commit/push) auf diesem Mount hinterlassen oft
   Lock-Dateien (.git/index.lock, HEAD.lock etc.), die den nächsten
   Git-Befehl blockieren. Funktionierendes Muster vor JEDEM Git-
   Befehl:
     find .git -name "*.lock" -exec sh -c 'mv "$1" "$1.old.$$"' _ {} \;
   Diese Zeile vor add, vor commit, vor push jeweils erneut ausführen
   (siehe Konversationsverlauf für exakte Befehlsketten).

c) Zum Bauen/Testen des Astro-Projekts (npm install / npm run build)
   NICHT direkt im gemounteten Ordner ausführen (npm/vite haben dort
   ähnliche EPERM-Probleme). Stattdessen mit rsync nach /tmp kopieren
   (ohne node_modules/.astro/dist/.git), dort installieren und bauen,
   Ergebnis prüfen. Auf dem echten Mac des Nutzers tritt dieses
   Problem NICHT auf (rein sandboxspezifisch).

d) GitHub-API (api.github.com) und Cloudflare-API (api.cloudflare.com)
   sind im Sandbox-Netzwerk-Proxy geblockt ("blocked-by-allowlist").
   Normales Git-Protokoll über github.com (Push/Pull/Clone) FUNKTIONIERT
   aber. Für alles, was echte API-Calls braucht (Repo per API anlegen,
   Wrangler-CLI-Deploy), auf Chrome-Browser-Steuerung (Claude in
   Chrome) oder den Nutzer selbst ausweichen.

e) Für GitHub-Push wurde bisher ein vom Nutzer im Chat geteiltes
   Personal Access Token verwendet (temporär in Bash-Befehlen, danach
   Remote-URL wieder auf Klartext zurückgesetzt, Token nie in Dateien
   gespeichert). Falls kein gültiges Token vorliegt: Nutzer nach einem
   neuen fragen oder ihn selbst pushen lassen.
